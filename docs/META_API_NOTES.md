# Meta Model API notes (verified 2026-10-27)
| # | Claim | Status | What the docs actually say (short quote) | Source URL |
|---|---|---|---|---|
| 1 | Base URL is https://api.meta.ai/v1; OpenAI-compatible Chat Completions and Responses. | confirmed | Quickstart specifies "the base URL `https://api.meta.ai/v1`" and supports both formats: "via Responses or Chat Completions". Compatibility has documented parameter restrictions; it is not complete OpenAI feature parity. | https://dev.meta.ai/docs/quickstart |
| 2 | Current Muse Spark and Muse Wonder model IDs. | confirmed | Docs list `muse-spark-1.1`, `muse-spark-1.2`, `muse-spark-1.3`, `muse-wonder-1.0`, `muse-spark-1.2-contributor`, and `muse-spark-1.3-contributor`. Spark 1.3 is "the latest version" and "Recommended for new work." All three Spark versions remain listed; these are not mutually exclusive names. Wonder Full is not a Model API model. This verifies the documented catalog, not access for a particular account. | https://dev.meta.ai/docs/models |
| 3 | Chat Completions accepts `developer` with highest precedence. | confirmed | `developer` is the "highest-precedence role you can set". It outranks `user`; `system` is accepted at the same level, so `developer` does not outrank `system`. | https://dev.meta.ai/docs/protocols/chat-completions |
| 4 | `response_format={"type":"json_schema","json_schema":{"name":...,"schema":...}}`; constrained decoding; `strict:false` behaves like `strict:true`. | confirmed | Output is always schema-constrained: "`strict: false` currently behaves the same as `strict: true` — output still conforms to the schema." The flag "only controls whether the server additionally validates your schema against the strict subset" (root plain object, no top-level `anyOf`/`oneOf`/`allOf`, etc.). `strict` defaults to `false`. (Corrected in review: the original row said the settings were not equivalent.) | https://dev.meta.ai/docs/structured-output |
| 5 | Recursive JSON schemas are rejected with HTTP 400. | confirmed | "A self-referencing `$ref` returns `HTTP 400` on both endpoints". The cookbook advises flattening the schema or bounding its depth. | https://dev.meta.ai/docs/cookbook/structured-output |
| 6 | Spark is tuned for temperature 1.0 / top_p 1.0; docs advise leaving defaults. | confirmed | Spark is tuned for defaults `temperature=1.0`, `top_p=1.0`; "Leave both unset for most workloads." This is advice, not a ban on supported sampling changes. | https://dev.meta.ai/docs/protocols/responses |
| 7 | `reasoning_effort:"none"` and `logprobs:true` return HTTP 400; valid reasoning-effort values. | partly | The Chat guide lists ""none", "minimal", "low", "medium", "high", "xhigh"" but explicitly rejects none for Spark; "`logprobs: true` returns `HTTP 400`". The reasoning guide says none is "Not supported by Muse Wonder or Muse Spark: returns `HTTP 400`." Valid non-none levels are minimal, low, medium, high, xhigh. That guide additionally lists "`"max"`" for `muse-wonder-1.0` and `muse-spark-1.3`, excluding `muse-spark-1.3-contributor`; the Chat and Responses endpoint guides omit max. Errors are documented, but the value lists differ. | https://dev.meta.ai/docs/protocols/chat-completions ; https://dev.meta.ai/docs/reasoning ; https://dev.meta.ai/docs/protocols/responses |
| 8 | Chat Completions supports `max_completion_tokens`; `max_tokens` is a deprecated alias; reasoning tokens count toward the cap. | confirmed | The parameter table names `max_completion_tokens`: "The deprecated alias `max_tokens` is still accepted." The reasoning guide says "Reasoning tokens count toward your output-token budget". The cap therefore covers reasoning plus visible output. Responses uses `max_output_tokens` instead. | https://dev.meta.ai/docs/protocols/chat-completions ; https://dev.meta.ai/docs/reasoning |
| 9 | Model IDs ending in `-contributor` permit use of prompts for training. | confirmed | Contributor mode exchanges lower prices for "permission to use your content to train future Meta models". Content includes prompts, code, files, context, and responses. Documented API variants are `muse-spark-1.3-contributor` and `muse-spark-1.2-contributor`; Wonder has no API Contributor variant. Standard mode excludes training use. | https://dev.meta.ai/docs/pricing-rate-limits |
| 10 | Automatic caching of identical prefixes; usage reports `cached_tokens`. | confirmed | "Meta Model API caches the stable prefix automatically". Matching is over leading token sequences, not arbitrary matching text. Usage paths are "`usage.prompt_tokens_details.cached_tokens`" for Chat Completions and "`usage.input_tokens_details.cached_tokens`" for Responses. A new prefix or eviction can produce zero cached tokens. | https://dev.meta.ai/docs/prompt-caching |
| 11 | Meta recommends Responses for multi-turn tool loops requiring reasoning continuity. | confirmed | Responses is "The recommended default for new work." Chat Completions has "No (reasoning is not carried between turns)" in the comparison table. Responses preserves reasoning using encrypted replay or `previous_response_id`; its guide recommends stateless encrypted replay. | https://dev.meta.ai/docs/protocols ; https://dev.meta.ai/docs/protocols/responses |
| 12 | Spark prices are $1.25 input / $0.15 cached input / $4.25 output per 1M tokens; rate limits. | confirmed | Standard Spark table lists "$1.25", "$0.15", "$4.25" for input, cached input, output respectively. Limits apply "per team, not per API key" and separately per model. Spark 1.1/1.2/1.3 and Wonder 1.0 each have 3,000 RPM / 4,000,000 TPM; Spark 1.2/1.3 Contributor each have 150 RPM / 3,000,000 TPM. These are published limits, not measured account quotas. | https://dev.meta.ai/docs/pricing-rate-limits |

## Implications for proofmerge/meta.py

- Configure the OpenAI SDK with `https://api.meta.ai/v1`; account for endpoint-specific restrictions (row 1).
- Use documented Standard IDs `muse-spark-1.3` and `muse-wonder-1.0`; catalog documentation does not establish account access (row 2).
- Prefer `developer` for standing instructions; `system` has equal precedence (row 3).
- Flatten or bound recursive output schemas before submission (row 5).
- Leave Spark sampling parameters unset for normal workloads (row 6).
- Budget reasoning and visible output together: `max_completion_tokens` for Chat Completions, `max_output_tokens` for Responses (row 8).
- Select Standard IDs when training permission is not intended; estimate Spark token costs and throttle using the published per-team limits (rows 9, 12).
- Prefer Responses for reasoning continuity in tool loops; retain encrypted reasoning or use server-managed history, and record endpoint-specific cached-token usage (rows 10, 11).
